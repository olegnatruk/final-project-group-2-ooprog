## Entity overview

```
User (abstract) ─┬─ RegularUser ──< AdoptionApplication >── Pet (abstract) ─┬─ Dog
                 └─ Admin              │                                     ├─ Cat
                                       │ 1 : 0..1                            └─ Bird
                                       ▼
                                 AdoptionRecord
```

- One `RegularUser` has many `AdoptionApplication`s.
- One `Pet` has many `AdoptionApplication`s, but at most one `APPROVED` at a time (ADR-013).
- One `APPROVED` application has zero or one `AdoptionRecord`.
- An `AdoptionRecord` stores `userId` and `petId` too, so history screens do not need to look up the application.

## IDs

| Entity | Format | Example | Owner of the class |
|---|---|---|---|
| User | `U` + 4 digits | `U0001` | Kurt |
| Pet | `P` + 4 digits | `P0001` | Julyan |
| Adoption application | `APP` + 4 digits | `APP0001` | Ace |
| Adoption record | `REC` + 4 digits | `REC0001` | Derick |

- Generated by `Repository.nextId()`: highest existing number + 1, zero-padded to 4 digits.
- IDs are never edited after creation (no setter).
- When a user types an ID, it is trimmed and converted to upper case before lookup, so `p0001` finds `P0001`.
- The seeded admin is always `U0001` on a fresh `data/` folder.

## Persistence

Files live in `data/` relative to the working directory (run from the repo root). `data/` is git-ignored.

**General format rules**
- UTF-8. One record per line. Fields joined with `|`. No header line. Blank lines are skipped.
- Split with `line.split("\\|", -1)` — the `-1` keeps trailing empty fields (see [GOTCHAS.md](GOTCHAS.md)).
- Enums: `name()` (e.g. `PENDING_ADOPTION`). Dates: ISO `yyyy-MM-dd`. Booleans: `true`/`false`.
  Doubles: plain `toString()` (e.g. `4.5`). Empty optional values: empty string.
- A line with the wrong field count or an unparseable value is **skipped with a warning** printed at startup;
  the rest of the file still loads.
- Each entity implements `core.Storable` with `toRecord()` (object → line). Each domain provides a static
  parser (object ← fields), e.g. `Pet.fromRecord(String[] fields)`.

### `data/users.txt` — 11 fields

```
userId|role|firstName|lastName|email|contactNumber|address|username|password|accountStatus|dateCreated
U0001|ADMIN|System|Administrator|admin@petadoption.com|09000000000|Pet Adoption Center|admin|admin123|ACTIVE|2026-10-14
```

### `data/pets.txt` — 14 fields

```
petId|type|name|breed|ageYears|gender|color|weightKg|description|healthInfo|vaccinationStatus|status|dateAdded|typeSpecific
P0001|DOG|Brownie|Aspin|2|MALE|Brown|12.5|Friendly and playful|Healthy, dewormed|FULLY_VACCINATED|AVAILABLE|2026-10-14|MEDIUM
```

`typeSpecific` by type: `DOG` → `DogSize` name; `CAT` → `indoorOnly` boolean; `BIRD` → `canFly` boolean. The
parser reads `type` first and creates the matching subclass.
